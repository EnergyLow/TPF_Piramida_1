# Караоке «Пирамида» — сайт

Адаптивный одностраничный сайт на HTML5, CSS3 и vanilla JavaScript (ES modules). Фреймворки и сборщик не требуются.

## Структура

```text
piramida-website/
├── index.html
├── css/style.css
├── js/main.js
├── js/menu.js
├── js/gallery.js
├── js/booking.js
├── backend/server.mjs
├── backend/package.json
├── backend/.env.example
├── data/menu.json
├── assets/icons/favicon.svg
├── privacy.html
├── robots.txt
├── sitemap.xml
├── .gitignore
└── README.md
```

## Запуск локально

ES-модули и `fetch()` корректно работают через HTTP, но не во всех браузерах при открытии `file://`.

1. Распакуйте проект.
2. Откройте папку в VS Code.
3. Установите расширение **Live Server** (если не установлено).
4. Нажмите правой кнопкой на `index.html` → **Open with Live Server**.
5. Проверьте мобильную ширину через DevTools, а также форму, категории меню и галерею.

Альтернатива при установленном Python: в корне проекта выполните `python -m http.server 8000`, затем откройте `http://localhost:8000`.

## Что реализовано

- Адаптивная вёрстка, мобильная навигация и плавные переходы.
- Загрузка демонстрационного меню из `data/menu.json`, категории и поиск.
- Галерея с модальным просмотром, Escape и стрелками.
- Форма бронирования подключается к Express API и показывает ошибки без потери заполненных данных.
- Telegram-уведомления администратору с кнопками подтверждения/отклонения и сохранением статусов в JSON.
- SEO-метаданные, Open Graph, JSON-LD без фиктивных рейтингов и графика работы.
- Страница-заготовка политики конфиденциальности, `robots.txt`, `sitemap.xml`.

## Перед публикацией — обязательный чек-лист

1. **Фотографии:** замените внешние демонстрационные изображения в `index.html`, `css/style.css` и `data/menu.json` локальными оптимизированными файлами в `assets/images/`. Не используйте фото без соответствующих прав. Для hero подготовьте WebP/AVIF и задайте корректный `og:image`.
2. **Меню:** полностью замените `data/menu.json`. Сейчас `demo: true`, цены `0` намеренно означают демонстрационные данные и не являются ценами заведения. Измените `demo` на `false` после проверки позиций.
3. **Акция дня рождения:** подтвердите условия, срок действия, ограничения и порядок получения; отредактируйте блок `#offers`.
4. **Бронирование:** разработайте HTTPS API, серверную валидацию, ограничение частоты запросов, защиту от спама, безопасное логирование и уведомления владельцу. Уведомления Telegram настраиваются только на сервере; токен бота нельзя помещать в клиентский JS. Затем задайте перед `main.js` конфигурацию, например:
   ```html
   <script>window.PIRAMIDA_CONFIG = { bookingEndpoint: 'https://ваш-домен.example/api/bookings' };</script>
   <script type="module" src="js/main.js"></script>
   ```
   API должен возвращать успешный HTTP-статус только после того, как заявка действительно принята. Ответ означает получение запроса сервером, а не окончательное подтверждение столика.
5. **Политика:** замените поля в `privacy.html`, уточните оператора, цели, основания, сроки хранения, контакты и реальные сервисы обработки. Нужна юридическая проверка перед сбором данных.
6. **Контакты:** перепроверьте телефон и адрес, подтвердите координаты, график работы и ссылку маршрута.
7. **Соцсети и отзывы:** добавьте только официальные ссылки и реальные отзывы с разрешённого/подтверждённого источника.
8. **SEO:** замените домен-заглушку в `sitemap.xml`, настройте canonical после выбора домена, проверьте JSON-LD и Open Graph.
9. **Аналитика:** добавляйте только после выбора инструмента и настройки требуемого механизма согласия.
10. **Фавикон:** при желании замените простой SVG-знак на утверждённый логотип.

## Подключение backend

Файл `js/booking.js` готов к подключению URL API, но сервер не входит в этот статический проект. Пример контракта:
- `POST /api/bookings`
- JSON: `name`, `phone`, `date`, `time`, `guests`, `comment`, `consent`
- сервер проверяет поля повторно, сохраняет заявку в защищённом хранилище и отправляет уведомление владельцу;
- ответ `2xx` выдаётся после фактического принятия заявки; ошибки возвращаются с соответствующим HTTP-статусом.

Не передавайте секреты и токены в браузер. В production обязательно используйте HTTPS.

## Публикация

Проект можно загрузить на любой статический хостинг (например, обычный веб-хостинг, GitHub Pages или Netlify). Загрузите все файлы с сохранением структуры и подключите домен. Для реального бронирования дополнительно разместите backend на сервере с HTTPS и укажите endpoint в конфигурации.

## Бронирование через Telegram (Node.js backend)

Требуется **Node.js 20 или новее**. Backend запускается отдельно от Live Server; не запускайте два экземпляра бота одновременно.

### 1. Создайте Telegram-бота

1. В Telegram откройте `@BotFather`, отправьте `/newbot` и следуйте подсказкам.
2. Скопируйте токен бота. Не отправляйте его в чат и не вставляйте во frontend.
3. Откройте созданного бота по username и нажмите **Start**.
4. Узнайте числовой Telegram ID администратора через надёжный инструмент для отображения ID. Для этой версии используйте личный чат администратора: `ADMIN_CHAT_IDS` должен содержать числовые Telegram user ID всех администраторов через запятую; для каждого администратора используется личный чат с ботом.

### 2. Настройте backend

В терминале VS Code:

```bash
cd backend
npm install
```

Скопируйте `backend/.env.example` в `backend/.env` и заполните `BOT_TOKEN` и `ADMIN_CHAT_IDS` (числовые ID через запятую). Каждый сотрудник должен открыть бота и нажать **Start**. Не коммитьте `.env`.

Windows PowerShell: `Copy-Item .env.example .env`  
macOS/Linux: `cp .env.example .env`

`ALLOWED_ORIGINS` должен содержать точный origin Live Server (по умолчанию порт 5500 или 5501). Если Live Server выбрал другой порт, добавьте его в `.env` и перезапустите backend.

### 3. Запустите backend и сайт

Из папки `backend` запустите:

```bash
npm start
```

API слушает `http://localhost:3000`. В другом терминале откройте корень проекта через Live Server. Форма отправляет запросы на `http://localhost:3000/api/bookings`. Проверка состояния: `http://localhost:3000/api/health`; `telegramConfigured: true` означает только наличие значений конфигурации.

### 4. Проверьте заявку и кнопки

1. Отправьте тестовую заявку с датой сегодня/позже, корректным телефоном и согласием.
2. В личные чаты всех администраторов из `ADMIN_CHAT_IDS` придёт сообщение с кнопками **Подтвердить** и **Отклонить**. Если один администратор обработает заявку, сервер обновит статус и уберёт кнопки во всех доставленных копиях.
3. Для проверки подтверждения создайте одну заявку и нажмите **Подтвердить**. Статус станет «Подтверждена», кнопки исчезнут.
4. Создайте вторую заявку и нажмите **Отклонить**. Статус станет «Отклонена».
5. Проверьте `backend/data/bookings.json`; проверьте валидацию пустых полей, прошлой даты и некорректного телефона.

### Ограничения и безопасность

- Успех показывается только после сохранения заявки и успешного ответа Telegram. При сбое Telegram форма сообщает об ошибке; запись с `notification_failed` сохраняется для диагностики.
- «Ожидает подтверждения» не означает, что стол свободен. Решение принимает администратор вручную.
- Используется Telegram long polling. При наличии webhook сервер не удаляет его автоматически и прекращает запуск polling с пояснением. Выясните, кто использует webhook, прежде чем отключать его. Одновременно должен работать один экземпляр polling.
- Inline-кнопки принимаются только от пользователей, чьи числовые ID перечислены в `ADMIN_CHAT_IDS`, и только из их личных чатов с ботом. Другие пользователи не могут менять статус заявки. Добавляйте в список только доверенных сотрудников.
- JSON-файл годится для локального теста, но не для надёжного многопроцессного production. Для публичного сайта используйте БД, HTTPS, резервное копирование, мониторинг и распределённый rate limiter. Текущий лимитер хранится в памяти и сбрасывается при рестарте.
- Для production замените `bookingEndpoint` в `index.html` на HTTPS URL размещённого API и внесите origin сайта в `ALLOWED_ORIGINS`. Не открывайте API публично до настройки HTTPS и политики обработки персональных данных.
- Для реальной проверки Telegram нужны собственные токен, ID и доступ к `api.telegram.org`; без них доставка не проверяется.
